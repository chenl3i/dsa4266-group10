**Project Title:** Nonlinear and Temporal Autoencoders for Network Attack Detection

# **Dataset Chosen and Description**

We propose to use UGR '16v2, a processed version of the UGR’16 network traffic benchmark collected at a Spanish internet service provider (Camacho & Rodríguez-Gómez, 2025; Maciá-Fernández et al., 2018). Each observation summarises one minute of traffic using 134 numerical flow counters, including protocol, source and destination IP-address categories, port categories, TCP flags, type of service, and packet-count and byte-count categories.

The supplied files contain 98,262 training observations from 19 March to 31 May 2016 and 43,200 test observations from 28 July to 26 August 2016\. Xtrain and Xtest contain the traffic features, while Ytrain and Ytest contain eight corresponding label counts. A shared timestamp links each minute’s features and labels.

Seven labels describe DoS, two scanning scenarios, Neris botnet activity, UDP scanning, SSH scanning and spam. The remaining label identifies traffic involving blacklisted IPs. We will exclude blacklist activity from the primary detection target because it reflects IP reputation and is present in every minute of these files. Preliminary checks show no positive training labels in the seven selected categories. We will therefore learn from background traffic without assuming that it is entirely benign.

# **Motivation**

Security Operations Centres must identify suspicious activity within large volumes of network traffic. Missed attacks can leave systems exposed, while excessive false alarms consume analysts’ time. This project will investigate whether nonlinear and temporal models can improve attack detection while keeping false alarms low.

We will compare a PCA baseline with autoencoders that reconstruct individual minutes or sequences of traffic. The study will ask whether nonlinear modelling improves on PCA, whether preceding minutes provide useful context, and whether recurrent or convolutional models make better use of that context. Earlier research on UGR’16 highlights the importance of data quality when comparing models (Camacho et al., 2023). We will therefore use a shared preprocessing and evaluation pipeline and will not assume that greater model complexity leads to better detection.

# **General Approach**

## **Data Cleaning and Exploratory Analysis**

We will parse the timestamp keys, sort each partition chronologically and align its feature and label files. Checks will cover missing or invalid values, duplicate timestamps, feature distributions and consistency between groups of counters. Any conflicting records will be investigated before modelling. We will preserve genuine traffic spikes because they may contain the anomalies of interest.

Exploratory analysis of the training data will use distribution plots, correlations and traffic-volume plots to examine skewness, redundancy and daily or weekly patterns. Recording gaps will be retained rather than filled with artificial traffic. Sequences will not cross these gaps. Preliminary test-label inspection will be acknowledged as dataset characterisation; test attack durations and feature–label associations will not determine model settings.

## **Preprocessing and Target Definition**

We will apply log(1+x) to reduce the effect of very large counts, then standardise the features so they are on a similar scale. The scaling values will be calculated using only the data used to train the models and applied unchanged to the validation and test sets. We will remove features that have the same value in every training record. Features that are mostly zero will be kept, as they may still help identify unusual traffic. Timestamps and label columns will not be used as model inputs.

For evaluation, we will label a minute as an attack if any of the seven non-blacklist label counts is greater than zero. We will also keep the individual labels to check how well the models detect each attack category. A minute with no positive labels will be treated as background traffic, although this does not guarantee that all traffic in that minute is harmless.

## **Training and Validation**

We will keep the provided training and test sets separate. Within the training set, we will use the first 78,609 records to train the models and the remaining 19,653 records for validation. The validation portion will be divided into an earlier block for tuning and early stopping and a later block for threshold calibration. All records will stay in time order without any shuffling.

The validation data contains no labeled attacks in our selected categories, so we cannot use it to check how well the models detect attacks. We will instead look at how closely each model reconstructs the input traffic and try a small number of model settings. We will keep the models simple, since lower reconstruction loss does not necessarily imply better attack detection. For PCA, we will choose the number of components based on how much variation they capture in the model-fitting data and compare nearby choices using the tuning portion of the validation set.

For each selected model, we will set the threshold at the 99th percentile of its calibration scores, corresponding to approximately a 1% calibration alert rate. All preprocessing parameters will be learned from the model-fitting data only. We will then apply the same preprocessing, trained models and thresholds to the test set without further changes. The false-alarm rate on the test set may differ because traffic patterns can change over time.

Model selection will use a predefined rule (the elbow of each model's validation loss curve), with sensitivity to neighbouring settings reported. As a sanity check, we will also verify that selected models detect synthetic anomalies injected into the tuning block using training-period statistics only.

## **Models and Experimental Setup**

**PCA baseline model:** The Principal Component Analysis will reconstruct each minute from a reduced set of components. Its mean squared reconstruction error will provide a simple linear anomaly score against which the autoencoders can be compared.

**MLP autoencoder:** The feedforward autoencoder will reconstruct individual minute-level feature vectors. Comparing it with PCA will assess whether nonlinear relationships between traffic features improve detection without using temporal context.

**Recurrent autoencoder:** The LSTM autoencoder to reconstruct windows of consecutive minutes and investigate whether temporal dependencies improve detection. A GRU variant will be considered as an extension if time and computing resources permit.

**1D Convolutional autoencoder:** The 1D-CNN autoencoder will also be trained on the same windows to capture local patterns over time. Its performance will be compared with the recurrent model using the same scoring method and a similar tuning budget. We will also track each model’s size and runtime.

Window lengths will be specified before model evaluation using operational considerations and prior literature. A window ending at minute t will contain only that minute and earlier observations, and will never cross a data gap or partition boundary. Temporal models will reconstruct their input windows, with the final minute’s mean squared reconstruction error used as the detection score. All models will be evaluated on the same eligible timestamps. A feedforward model on flattened windows will provide an additional control for the benefit of temporal input.

# **Evaluation**

We will evaluate all predefined comparisons after model settings are fixed. Because attack minutes are uncommon, accuracy alone will not be used to judge performance. The evaluation will distinguish performance at the frozen calibration threshold from comparisons across possible thresholds.

**At the frozen threshold:** We will report recall, precision, F1, observed false-positive rate and total alert rate. This will show how well each model detects labeled attacks and how its alert burden changes on later traffic.

**Across thresholds:** Average precision will summarise the precision–recall trade-off. We will also report recall at a test FPR no greater than 1% and standardised partial ROC-AUC over FPR 0–1% as retrospective comparisons. These test-derived operating points will not replace the frozen threshold.

We will report recall and sample counts for each attack category present in the test data, without expanding a single detected minute into a correctly detected entire episode. Neural experiments will use three recorded random seeds. We will compare variability, training time and inference time alongside detection performance.

# **Limitations and Risks**

Minute-level aggregation may dilute brief or low-volume attacks and remove the ordering of flows within each minute. Temporal windows may help identify patterns across minutes, but cannot recover this lost detail. Moreover, background training traffic may contain unlabeled anomalies, and excluding blacklist activity narrows the scope of the evaluation.

Changes in traffic between the training and test periods may increase false alarms even when the calibration alert rate is low. We will report the observed test false-positive rate rather than assume that the calibration threshold transfers unchanged in performance. Some attack categories have very few labeled examples or are absent, limiting conclusions about those categories.

The data represents one ISP environment in 2016\. Results will establish performance on this benchmark rather than demonstrate readiness for current networks or previously unseen attacks. Autoencoders may also reconstruct malicious traffic well. Our analysis will therefore assess whether the proposed models offer a useful improvement over PCA, including the possibility that they do not.
